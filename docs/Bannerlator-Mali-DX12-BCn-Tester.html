The DX12 + BCn driver for Mali

A new, opt-in graphics driver that brings DirectX 12 games to Mali GPUs and keeps the BCn texture support you already have — in a single dropdown choice. This guide explains exactly what it is, which devices it works on, what to change, and how to report back.

⚗ EXPERIMENTAL — test build Driver: Wrapper + compat + bcn For Mali devices Build 2c20cfa · standard · v 2.6.2
In one line: select the new “Wrapper + compat + bcn” graphics driver on a Mali device and DirectX 12 games can now run through it, on top of the existing BCn texture decode. Nothing changes for the drivers you use today, and Adreno/Qualcomm devices are unaffected. It is experimental — some games or GPUs won’t work yet, and that’s what this test is for.

1 What this driver is

And how it differs from what Bannerlator ships today.

Bannerlator already offers a “Wrapper + bcn_layer” driver for Mali. It fixes BCn textures — the compressed textures (BC1–BC7) that many DX9/DX10/DX11 games use, which Mali can’t read natively and would otherwise show as black/broken or crash the game. That driver decodes them on the GPU so those games render correctly.

What it cannot do is run DirectX 12 games. DX12 goes through a translator (VKD3D) that needs Vulkan features Mali drivers don’t expose, so DX12 titles fail to start on Mali.

The new “Wrapper + compat + bcn” driver adds a second component — a Mali compatibility layer — that emulates exactly those missing DX12 features. The result is a single driver that does both:

Capability“Wrapper + bcn_layer” (today)“Wrapper + compat + bcn” (new)
BCn textures (DX9–11)✅ Yes✅ Yes — unchanged
DirectX 12 games❌ No✅ Yes — on supported GPUs
Runs onMali / Xclipse / other non-AdrenoMali (see requirements below)

It is purely additive: BCn behaves exactly as before; DX12 is the new part.

Both drivers stay — you choose

This build adds “Wrapper + compat + bcn” next to the existing “Wrapper + bcn_layer”. It does not replace it — both remain selectable in the dropdown, and every other driver is untouched.

  • ✓Keep using “Wrapper + bcn_layer” if you don’t need DX12. It’s the proven path, with no DX12 emulation overhead and no hardware floor.
  • •Pick “Wrapper + compat + bcn” when you want to run a DX12 game (or to A/B test — run the same game on each and tell us what differs).

Why not just one driver? Because the new stack is unproven on real hardware, and folding DX12 emulation into the one driver that Mali users rely on today would risk their working setup with no fallback. Long-term goal is a single Mali driver — if testing shows the new one does everything the old one does with no regression, a future stable may merge them into one (your existing game shortcuts would migrate automatically). But only after it’s proven on real Mali devices — which is what this test decides.

2 Which devices it works on

The DX12 part has a hardware floor. BCn support is unchanged and broader.

✔ DX12 supported

  • ›Valhall Mali on driver r32p1 or newer — G57, G68, G77, G78, G310, G610, G710, G615, G715, G720, G925.
  • ›These meet the Vulkan 1.3 / descriptor-indexing requirements the DX12 layer needs.

✗ DX12 not supported

  • ›No Vulkan 1.3: Mali-G51, G71, G31 (Bifrost) and G72 on drivers older than r44p1.
  • ›No descriptor-indexing: Mali-G52, G76 (Bifrost).
  • ›Midgard: Mali-T830, T880 and older; and any driver older than r32p1.
The DX12 part is meant for the supported GPUs listed above. On a GPU below that floor, expect DX12 games not to launch (or to misbehave) — that’s a limitation of the hardware, not a bug to report. BCn texture support has no such floor and keeps working on the same Mali devices it does today; if you only need BCn, use the “Wrapper + bcn_layer” driver instead. Part of what this test measures is exactly where the DX12 floor really falls on real devices.

3 How to use it & the new settings

Selectable per-container and per-game (shortcut) just like every other driver.

  1. Open Container Settings (or a game’s Shortcut Settings) → Graphics Driver.
  2. Choose “Wrapper + compat + bcn” from the dropdown.
  3. Adjust the options below if needed, save, and launch.

The existing BCn Layer Settings panel appears for this driver (same as the current BCn driver), plus one DX12 option:

  • •Force decode on all GPUs — forces BCn texture decoding (recommended default for Mali).
  • •Transcode to ETC2 / Transcode to ASTC — target format for decoded textures; leave default unless a game misbehaves.
  • •Storage image path — internal BCn transfer method; default is fine.
  • •Emulate sparse binding (DX12) — off by default. Turn on only for DX12 games that use tiled/reserved resources and otherwise glitch or crash. It’s not free, so don’t leave it on globally.
  • •Debug log — writes BCn/DX12 diagnostics to the Wine debug log (enable Settings → Logs → Wine Debug to capture it). Use this when reporting a problem.

4 Adreno / Qualcomm devices

Short version: you are not affected.

  • ✓This driver is opt-in — it only does anything if you deliberately select it.
  • ✓Adreno GPUs already have native BCn and native DX12 support, so there is no reason to use it.
  • ✓Even if selected on Adreno, the emulation layers are gated off by a hardware check — the same guard that already skips the current BCn driver on Adreno, now extended to cover this one. No overhead, no behaviour change.
  • ✓Every existing driver (Turnip, Wrapper-original, Wrapper-gamenative, Wrapper + bcn_layer, …) is completely untouched. This build only adds a new option.

5 How to test & what to report

This is the whole point of the build — your results decide whether it ships.

  • 1.Note your device, Mali GPU model, and driver version (e.g. “Mali-G57, r32p1”).
  • 2.Test a DX12 game (the new capability) and a BCn DX11 game (confirm it still works).
  • 3.For each: does it launch? Do textures look right? Roughly what FPS? Any crash or glitch?
  • 4.If something fails, enable the Debug log option + Wine Debug and attach the log.
  • 5.Compare against “Wrapper + bcn_layer” on the same game where relevant, so we can see the difference.
Heads-up: this stacks two emulation layers (BCn + DX12) that both adjust what the game sees. It’s new and unproven on real hardware — some combinations may conflict, run slowly, or not start. None of that is unexpected in a test build; clear reports of what game, what GPU, what happened are exactly what we need.
